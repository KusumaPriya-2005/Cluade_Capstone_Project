## Changelog entry (added to `CHANGELOG.md`, section Unreleased)
Added
- `pwreset`, a standard-library-only Python library (3.11 or later) for password reset via a registered email address.
- Request reset and confirm reset operations, with injectable clock, token generator, email sender and repositories.
- Single-use, expiring reset tokens (30 minute default, exclusive expiry). Only a hash of the token is stored, and a newer token invalidates older ones.
- Password hashing with scrypt (per-password salt) and NFKC normalisation of passwords, plus a configurable password policy (12 to 128 characters, denylist, not equal to the email, no reuse of the current password).
- Uniform response for requests, so registered, unknown, malformed and rate-limited emails cannot be told apart.
- Sliding-window rate limiting: 5 requests per hour per email, 20 per hour per client, and 10 invalid confirm attempts per hour per client.
- Session-revocation hook, called once with the user id after a successful reset.
- "Your password was changed" notification sent after a successful reset.
- In-memory user and token repositories.
- pytest suite of 125 tests covering all acceptance criteria. It needs no network and no sleeps.
- README with usage and security notes.

## PR description

### Summary
Adds `pwreset`, a small standard-library-only Python library that lets a user who forgot their password request a reset through their registered email and set a new password with a secure, expiring, single-use token. It resists account enumeration and abuse. There is no web layer, real email or real database. Email, clock, token generation and storage are injected.

### Linked requirements
- FR-1 to FR-13 (request, uniform response, token generation, expiry, single use, confirm, password policy, scrypt storage, rate limiting, email normalisation, session-revocation hook, change notice, repository abstraction).
- NFR-1 to NFR-7 (security, no leaks in logs, exceptions or `repr`, stdlib only, deterministic tests, typing and docs, atomic-consume-friendly interfaces). NFR-5's 90% branch coverage target is unverified.
- AC-1 to AC-16, all met per `07-verification.md`.

### Changes
- `src/pwreset/`: service, config, errors, hashing (scrypt with NFKC normalisation), password policy, rate limiter (sliding window), interfaces, in-memory repositories, system clock and token generator.
- `tests/`: 125 pytest tests in 10 files plus `conftest.py`.
- `README.md`: usage and security notes. `pyproject.toml`: `requires-python >=3.11`, pytest as the only dev dependency.
- `CHANGELOG.md` entry. `.gitignore` now ignores Python bytecode and the pytest cache.

### Risks and accepted trade-offs
- R4, R5, R8, R9 and R10 (including ordering note B3) are known, accepted and documented in the README. There is no timing-equality claim.
- In-memory stores and rate limiter are not thread-safe and not persistent. A real deployment needs atomic token consumption in its repository.
- Passwords are NFKC-normalised before hashing. This was accepted, and callers must apply it consistently with any existing hashes.
- A user id is never logged on revoker failure (the request was declined). Only fixed event text and the exception class name are logged.
